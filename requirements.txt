# What ships in the Lambda deployment package (/var/task) - `sam build`'s
# default Python builder reads exactly this file, with no way to point it at
# a differently-named one without a custom Makefile build step (which is
# more machinery than this needs). So: this file is deliberately Lambda-
# shaped, not "everything local dev needs" - see requirements-dev.txt for
# that.
#
# pandas/numpy are intentionally NOT here even though league_reports/reports/*.py
# import pandas: the AWSSDKPandas-Python311 layer (template.yaml,
# DESIGN.md decision #3) already provides pandas+numpy at /opt/python for
# the deployed Lambda. Bundling pandas here too would (a) make `sam build`
# resolve/download pandas's own dependencies via pip, which is what broke
# the build outright - pandas' unpinned `numpy>=1.23.2` floor let pip
# resolve to a numpy release with no linux/cp311 wheel yet - and (b) even on
# a day that resolves fine, AWS's docs say deployment-package versions
# shadow layer versions on the import path, so a bundled pandas would
# silently win over the layer's pandas instead of the layer actually being
# used - defeating the reason decision #3 picked the managed layer over a
# container image in the first place.
